# Gate v2: a consistency-based score for the review gate (2026-11-07, branch `gate-v2`)

Queue item 28, follow-up to MATH v2 (b) (`docs/research/MATH_V2_2026-11.md`). **All data is SYNTHETIC** (the
Japanese extraction corpus and its separately written holdout generator). Humans decide: the gate only flags
values for review.

**Result: holdout target missed.** Coverage of wrong values on the independent holdout went from 0.333 to
**0.767** (46 of 60). The target was ≥ 0.90. The share of correct holdout values flagged rose from 0.489 to
0.687. Because the target was missed, **the default gate is unchanged**: no Rust change, and
`calibration.json` is untouched (`gate_bps` 0).

## What changed

- `services/extraction/tests/ja_eval.py` now keeps each mapped value's predicate, value, unit, tolerance and
  source location in the claim rows, plus each document's records and unmapped labels (`doc_meta`).
  Existing consumers (`ja_calibrate.py`, `ja_conformal.py`) ignore the extra keys.
- `services/extraction/tests/ja_gate2.py` holds the new score, the split-conformal fit and the measurement.

### Score

Each value gets a set of inconsistency signal families. All of them are computed from data the extractor and
mapper already produce:

| family | signal |
|---|---|
| forced | the mapper always flags it: OCR < 0.80, or a guessed label or subject. This is the previous gate. |
| shape | the value does not have its field's shape: ISO date 1990–2040, pass/fail enum, grade code, company name, person name, revision, scale, positive quantity |
| unit | the unit does not belong to the field's dimension (length, stress, %, hardness scale) |
| range | outside generic engineering bounds. The bounds come from handbooks, are wide, and were not fitted to the corpus. |
| spec | a measured value lies more than 5 tolerance widths from nominal, or the tolerance is more than 25 % of nominal |
| cross | yield ≥ tensile, chemistry sum > 100 %, or a table row's pass/fail disagrees with its measured values vs nominal ± tolerance |
| dup | a single-valued field of one subject is mapped twice in one document with different values |
| table | the value's table row (htable: column) has a different cell count from the table's modal count |
| novel | the printed label (table cell: its column header) never occurs in the train + dev documents |
| xdoc | the same part/heat has a different material, nominal, tolerance, drawing number or part name in another document |

`score = −10 000 × (number of families raised)` when at least one family is raised, otherwise `p_correct_bps`.
p_correct is deliberately not a tie-breaker inside a signal class. 54 of the 55 calibration wrong values are
forced, low-p OCR values, so a p tie-break would teach the threshold "low p", which is exactly what failed on
the holdout. The split-conformal threshold (k = ⌈0.9(n+1)⌉-th smallest score of the n = 55 dev + dev_scan
wrong values) came out at −10 000, so the fitted gate means "flag every value that raises at least one signal".

### Holdout discipline

The signals, bounds and score were designed using train and dev data only (`--no-holdout`). They were
committed (ecbf244, "frozen before holdout evaluation") **before** the holdout was evaluated with them. The
holdout was then scored once. Nothing was changed afterwards; the per-family table and the miss analysis
below are post-hoc explanation only.

## Why the target was missed (post-hoc, not used to change anything)

- **12 of the 14 missed values are wrong-subject values.** The value is right, but its subject key is not an
  identifier: `寸法`, `DRAWING NO.`, `亜鉛めっき(三価)`, `カラー`. The mapper took a header or a material/finish
  text as the part. Every signal here checks the *value*; none checks the *subject key's* shape. A subject-shape
  signal (a part/drawing/heat key must look like an identifier) is the obvious next family. It was not added
  after seeing these misses, because that would be tuning on the holdout. It needs a fresh holdout to be
  measured honestly.
- The other 2 misses are an approval mark and a checker name (`APPD`, a column header read as a name) on a
  drawing title block. The person-name shape check only rejects digits.
- **The review load comes mostly from `novel`.** 25 correct holdout values were flagged by label novelty alone,
  18 of them in the new purchase-order layout. `novel` also catches 11 wrong values that nothing else catches.
  On the calibration documents a leave-one-layout-family-out run flags 12 % of correct values (161 / 1 350) and
  catches 2 / 55 wrong values. So it is a broad "this layout is new" signal, not a precise one.
- `spec`, `cross` and `range` never fired on the holdout. Its errors are association errors (wrong subject,
  wrong label → field), not implausible numbers.
- **Not measurable on this corpus:**
  - Cross-document consistency: no part or heat appears in more than one document, so `xdoc` fired 0 times.
  - OCR vs text-layer disagreement: not implemented. It would need an OCR pass over every text PDF, which is
    not cheap. It also would not help here, because both layers carry the same text and the holdout errors are
    in the mapping, not in the characters.
- The conformal guarantee still needs exchangeability. The calibration wrong values (54/55 forced) say nothing
  about how often the signals miss. The −10 000 threshold is valid for dev-like data only.
