# MATH v2: statistics upgrades (2026-11-06, branch `math-v2`)

Queue item 27. Everything is **library-first** (pure, deterministic functions with unit + property tests). Every
number below comes from a real run of the command named under it, on this host (8 vCPU, load average 12–15 from
other lanes, so ignore wall-clock times). **All data is SYNTHETIC** except (b), which uses the synthetic Japanese
extraction corpus. The generators and the methods were written together, so the numbers show behaviour on known
patterns, not accuracy on real supplier data. Where a target was missed it says so.

Humans decide: every method here only ranks, flags for review or suggests. Nothing rejects evidence, merges
entities or changes / reverses a recorded decision.

## (a) Multiple-testing control for integrity signals

Code: `crates/quality-stats/src/multitest.rs` — Fisher and weighted Stouffer combination, Benjamini–Hochberg and
Benjamini–Yekutieli adjusted p-values, conformal p-values, `SupplierCalibration` (1-stage: conformal p of a
certificate's Fisher score against the supplier's own cleared certificates) and `conformal_combined_p` (2-stage,
fully conformal: per-test conformal p first, then Fisher, then a conformal p of that; exactly valid when the new
certificate is exchangeable with the supplier's cleared ones).

Command: `cargo run --release -p quality-stats --example math_v2_eval a` (seed 20261106).
Per certificate 7 tests (terminal-digit χ², 0/5 heaping, variance-too-low for 5 characteristics). S3 has a gauge that
only shows …0/…5 last digits (honest), S4 states σ0 1/0.6× too high (honest data looks "too consistent").
Test set per supplier: 400 honest, 40 tidied (30 % of last digits to 0/5), 40 smoothed (sd × 0.5). α = 0.01.

Findings:
- Fisher/Stouffer alone fix the multiplicity of independent tests (S0–S2: 0.05–0.075 → ≈ 0.01) but not supplier
  quirks (S3, S4 stay at 0.90–1.00). Per-supplier calibration fixes both: **every supplier ≤ 0.018**.
- In a batch, the union rule's flags are 2/3 false; calibrated flags ≈ 5 % false (BH at q = 0.2 holds 0.10–0.105).
- **Cost**: tidied last digits are a sparse signal (2 of 7 tests). Fisher-type combination dilutes it: recall drops
  from 0.85–0.95 (union) to 0.30–0.78; the 2-stage version is worse here than 1-stage because per-test conformal
  p-values are floored at 1/(n+1). For S3 tidying is undetectable by construction (its honest digits are already
  0/5). Smoothing (dense signal) recall stays ≥ 0.975 except S3 1-stage (0.475 / 0.800).
- BH needs enough references: with 100, the conformal p floor (0.0099) is above q·rank/m for q = 0.05, so BH
  rejects nothing. Use ≥ 400 cleared certificates per supplier, or report the union and calibrated views side by side.
- Calibration is only as good as the references: a manipulated certificate cleared by mistake makes it more permissive.

## (b) Conformal review gate

Code: `crates/quality-stats/src/conformal.rs` (`ConformalGate`: k = ⌈(1 − α)(n + 1)⌉-th smallest score of the
calibration wrong values, flag if score ≤ it; all flagged if k > n). Python mirror in
`services/extraction/tests/ja_calibrate.py` (`conformal_threshold`, now used to choose `gate_bps`); score = −1 for
values the mapper always flags (OCR confidence < 0.80, guessed label or subject), else calibrated p_correct.
Refitting with it reproduces the shipped `calibration.json` byte-for-byte in content (gate 0).

Commands: `uv run python tests/ja_eval.py --holdout --rust target/release/examples/map_records --out ev.json`
(1 596 mapped values; 55 wrong on dev + dev_scan, 60 on holdout + holdout_scan), then
`uv run python tests/ja_conformal.py ev.json --reps 1000 --seed 20261106`.

| experiment | rule | mean coverage | 5th pct coverage | splits ≥ 0.90 | review load |
|---|---|---|---|---|---|
| E1 dev splits (27 cal / 28 test wrong) | conformal | 0.9805 | 0.9643 | 1.000 | 0.434 |
| | previous empirical rule | 0.9805 | 0.9643 | 1.000 | 0.434 |
| E2 pooled dev + holdout splits (57 / 58) | conformal | 0.9987 | 1.000 | 0.995 | **0.999** |
| | previous empirical rule | 0.9934 | 1.000 | 0.973 | 0.994 |
| E3 fit dev → independent holdout (60 wrong) | conformal (threshold −1) | **0.333** | – | – | 0.440 |
| | previous empirical rule (threshold −1) | 0.333 | – | – | 0.440 |

Findings:
- On exchangeable data the guarantee holds (E1, E2; the conformal rule keeps ≥ 0.90 in 99.5 % of E2 splits vs 97.3 %
  for the old rule, which has no finite-sample correction).
- **Holdout target missed: 0.333.** 40 of the 60 holdout wrong values are text-layer values mapped by a rule with
  calibrated p_correct 0.9959–0.9986: the score is confidently wrong on the new layout family. No threshold on this
  score can catch them without flagging every text value (E3 "needed for 90 %": threshold 9986, review load 1.000;
  E2 shows the same — coverage bought with load 0.999). The fix is a better score (layout novelty, cross-field
  consistency), not a better threshold. E1 is also optimistic because the calibration table was fitted on dev.

## (c) Monte Carlo tolerance stack-up

Code: `crates/tolerance/src/mc.rs` — `monte_carlo` over a dimension loop with per-link `Distribution` (Normal,
Uniform, Triangular, shifted log-normal left/right skew, Johnson); links without one use exactly the normal model of
`analyze()` (refactored into `stack::link_model`). Johnson SU/SB/SL fit from data by the Slifker–Shapiro (1980)
percentile method; Pearson type from β₁, β₂ and κ (diagnostic only; sampling uses Johnson). Yield gets a Wilson 95 %
interval; deterministic SplitMix64 per seed.

Command: `cargo run --release -p tolerance --example mc_eval` (n = 100 000, seed 2026). BEFORE = `analyze()`
predicted_yield (normal approximation) with no process data (Cp = 1, what main does) and with the true/fitted σ.

| case | truth | BEFORE Cp=1 | BEFORE σ-matched / fit | AFTER MC [95 % CI] | err Cp=1 | err σ/fit | err MC | CI covers |
|---|---|---|---|---|---|---|---|---|
| 1 four uniform links | 0.973633 (exact Irwin–Hall) | 0.999823 | 0.969617 | 0.973690 [0.972680, 0.974664] | 2.62e-2 | 4.02e-3 | 5.72e-5 | yes |
| 2 triangular links | 0.994921 (MC 10⁷) | 0.999929 | 0.982551 | 0.995650 [0.995223, 0.996039] | 5.01e-3 | 1.24e-2 | 7.29e-4 | **no** |
| 3 skewed log-normal link | 0.985033 (quadrature) | 0.996108 | 0.964840 | 0.984940 [0.984166, 0.985676] | 1.11e-2 | 2.02e-2 | 9.28e-5 | yes |
| 4 Johnson fit from 500 parts (true log-normal) | 0.985033 | 0.996108 | 0.971922 (normal fit) | 0.987930 [0.987234, 0.988588] | 1.11e-2 | 1.31e-2 | 2.90e-3 | **no** |

Wilson 95 % coverage over 500 seeds (n = 10 000 each): 0.964 (case 1, exact truth), 0.948 (case 3).

Findings: MC error is 10–400× smaller than the normal approximation in cases 1–3; with the right σ but the wrong
shape the normal approximation is still off by 0.4–2 % yield. Case 2's miss is chance (3.3 SE; over 300 seeds the
MC spread equals the binomial SE). Case 4's miss is fitting error from 500 parts, which the CI does not cover (it
covers Monte Carlo error only); Johnson still cuts the error ≈ 4.5× vs a normal fit. Fit chose SU (Pearson type VI
from the sample, as for a true log-normal). Limits: the CI says nothing about whether the input distributions are
right; n ≤ 5·10⁷ (draws kept for quantiles); SL/normal selected only when the quantile ratio is within 1e-6 of 1.

## (d) Short-run SPC and Bayesian online change-point detection

Code: `crates/quality-stats/src/spc/short_run.rs` (`q_chart` — Quesenberry 1991, μ and σ unknown, from the 3rd value;
`q_chart_known_sigma`; `dnom`, `dnom_standardized`) and `spc/bocpd.rs` (Adams & MacKay 2007, Normal–inverse-gamma,
constant hazard, run-length truncation). Q points feed the existing `check_rules` (centre 0, σ 1).

Command: `cargo run --release -p quality-stats --example math_v2_eval d`. 4 000 series of 30 values per row, μ and σ
unknown and random, shift δσ at value 16. I-MR = limits from the first 10 values (all a short run allows).
Columns = share of series with an alarm (δ = 0: any alarm = false alarm; δ > 0: first alarm at/after the shift).

| δ | I-MR rule 1 | I-MR WE | Q rule 1 | Q WE | BOCPD | median delay I-MR WE / Q WE / BOCPD |
|---|---|---|---|---|---|---|
| 0 (false alarms) | 0.247 | 0.426 | 0.079 | 0.258 | 0.035 | – |
| 1 | 0.349 | 0.686 | 0.084 | 0.501 | 0.046 | 4 / 5 / 3 |
| 2 | 0.676 | 0.860 | 0.184 | 0.867 | 0.243 | 2 / 3 / 2 |
| 3 | 0.844 | 0.851 | 0.388 | 0.896 | 0.598 | 1 / 1 / 1 |

DNOM (6 part numbers × 5 pieces, one process, Q-chart with WE rules on x − nominal; per-part charts impossible):
any alarm 0.239 without a shift; detection at/after the shift 0.746 (1.5σ) and 0.898 (3σ).

Findings: with 10-value Phase I limits, I-MR raises a false alarm in 25 % (rule 1) / 43 % (WE) of in-control runs
(the estimated limits are noisy). The Q-chart's false-alarm rate matches theory (rule 1: 0.079 vs 28 × 0.0027 =
0.076) and with WE rules equals I-MR's power at 2–3σ with 40 % fewer false alarms; it is weak at detecting a shift
with rule 1 alone because the running mean absorbs a sustained shift. BOCPD at P(run < 5) > 0.5 has the lowest
false-alarm rate (0.035) but low power below 3σ; its threshold was not tuned (a matched-FPR comparison is open).

## (e) Variance too low: likelihood-ratio / Bayesian

Code: `crates/quality-stats/src/integrity/variance.rs` — `variance_too_low_pooled` (common shrink factor λ across a
certificate's characteristics; the LR is monotone in T = Σ(nᵢ − 1)sᵢ²/σ_ref,ᵢ², UMP for H1: λ < 1),
`shrink_posterior` (log-uniform prior on λ, Bayes factor and P(λ < c); same ranking as the pooled LR for fixed df)
and `variance_too_low_estimated_sigma` (exact F test when σ0 comes from a gauge study with ν df).

Command: `cargo run --release -p quality-stats --example math_v2_eval e`. 4 000 honest + 4 000 manipulated per row,
σ0 = 0.05, 10 repeats per characteristic. New thresholds set on a separate honest set to the existing test's FPR.
Rows K = 1 are the sets of the existing calibration (`examples/calibrate.rs`).

| chars | smoothed | sd factor | existing FPR | existing recall | pooled-LR FPR | pooled-LR recall | Bayes-factor FPR | Bayes-factor recall |
|---|---|---|---|---|---|---|---|---|
| 1 | 1 | 0.5 | 0.0103 | 0.501 | 0.0100 | 0.500 | 0.0100 | 0.500 |
| 1 | 1 | 0.7 | 0.0118 | 0.105 | 0.0118 | 0.105 | 0.0118 | 0.105 |
| 5 | 5 | 0.5 | 0.0475 | 0.973 | 0.0467 | **1.000** | 0.0467 | 1.000 |
| 5 | 5 | 0.7 | 0.0500 | 0.436 | 0.0508 | **0.956** | 0.0508 | 0.956 |
| 5 | 2 | 0.5 | 0.0442 | 0.765 | 0.0498 | 0.465 | 0.0498 | 0.465 |
| 5 | 2 | 0.7 | 0.0460 | 0.219 | 0.0428 | 0.231 | 0.0428 | 0.231 |

σ0 estimated by a gauge study (ν = 10), K = 1, nominal α = 0.01:

| test | FPR honest | recall sd 0.5·σ0 | recall sd 0.3·σ0 |
|---|---|---|---|
| existing χ² (σ̂0 treated as exact) | 0.0190 | 0.456 | 0.919 |
| F test | 0.0107 | 0.345 | 0.871 |

Findings:
- **Target (recall > 0.8 at the same FPR) met only by pooling**: when the whole table is smoothed, 0.956 vs 0.436
  (sd 0.7·σ0) and 1.000 vs 0.973 (sd 0.5·σ0).
- **Not met for a single characteristic**: the existing lower-tail χ² is already the uniformly most powerful test for
  one sample; LR and Bayes factor give the identical ranking (0.500 / 0.105). No method can do better on that data.
- When only 2 of 5 characteristics are smoothed the common-λ model is wrong and pooling is worse (0.465 vs 0.765);
  keep the per-characteristic test alongside.
- The Bayes factor ranks exactly like the pooled LR (identical rows); its value is the readable posterior
  ("sd ≈ 0.5× stated, P(λ < 0.8) = 0.99").
- With an estimated σ0 the existing test's FPR is 1.9× nominal; the F test restores it (0.0107) at a recall cost.

## (f) Active learning for entity resolution

Code: `crates/entity-resolution/src/v2/active.rs` — `ActiveModel` turns the EM Fellegi–Sunter m/u/p into
Dirichlet/Beta pseudo-counts (prior strength 10), adds each reviewer decision as a count (closed-form refit,
deterministic), and `order_queue` puts the most uncertain pair first (|log-odds| ascending, seeded-hash tie-break).
Decisions are append-only inputs; the model only orders the queue and suggests.

Command: `cargo run --release -p kizuna-bench --bin kizuna-er-active -- --out reports/er/er_active_learning.json`
(seeds 20261105/20261106; simulated reviewer answers from truth; refit after every decision). F1 over all true
pairs; unsurfaced true pairs count as FN for every strategy. BEFORE = current queue (weight descending; unreviewed
pairs predicted match only if the outcome is `match`); weight_model = same order, model prediction; random; AFTER =
uncertainty sampling.

| dataset (keys) | typo rule | queue (true) | F1@0 before / model | reviews to F1 0.99: before | weight_model | random | after |
|---|---|---|---|---|---|---|---|
| dense parts (1000) | default | 1668 (1391) | 0.554 / 0.981 | 1518 | 1518 | 707 | **133** |
| dense parts (1000) | broad | 2111 (1391) | 0.544 / 0.981 | 1817 | 1817 | 924 | **458** |
| dense parts (5000) | default | 8911 (7487) | 0.519 / 0.984 | 8180 | 8180 | 3828 | **898** |
| dense parts (5000) | broad | 12297 (7500) | 0.503 / 0.983 | 10183 | 10183 | **4985** | 10348 |
| sparse parts (1000) | default | 455 (429) | 0.766 / 0.986 | 428 | 428 | 59 | **15** |
| sparse parts (1000) | broad | 540 (429) | 0.749 / 0.986 | 477 | 477 | 175 | **16** |
| sparse parts (5000) | default | 2411 (2244) | 0.736 / 0.986 | 2274 | 2274 | **696** | 2204 |
| sparse parts (5000) | broad | 2819 (2247) | 0.720 / 0.986 | 2464 | 2464 | **580** | 2229 |
| suppliers (300) | – | 499 (420) | 0.349 / 0.599 | not reached (ceiling 0.617: 526 true pairs never surfaced) | | | |

Findings: most of the F1 gain at 0 reviews (0.50–0.77 → 0.98) is the prediction rule (posterior ≥ 0.5 instead of
"only `match` counts"), not active learning — the EM thresholds are deliberately conservative. Uncertainty sampling
reaches F1 0.99 with 4–30× fewer reviews than the current order on 4 of 8 part configurations and beats random
there by 2–8×, but **on 3 of 8 (5000-key broad, both sparse 5000) it is 3–4× worse than random** and no better than
the current order. Likely cause (not verified): it keeps sampling one comparison pattern where true pairs and
different parts share the same γ (typo vs sibling part), so the posterior stays near 0.5. Not tried: a cap per γ
pattern or mixing in random picks; only one prior strength and one seed per dataset. Suppliers: recall is limited by
blocking, not by review order. Treat (f) as a promising but **unreliable** ordering; do not ship it as the default
queue order without the mitigation.
