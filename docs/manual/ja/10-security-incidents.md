# セキュリティインシデントと封じ込め

画面：「管理」›「セキュリティ監視」。インシデントの対応は管理者が行い、監査担当は閲覧できます。

KIZUNA は自身のセキュリティイベント（直近 1 時間分を毎分チェック）を監視し、ルールに該当するとインシデントを
作成します。対応は KIZUNA 内のセッション、アカウント、アップロード、文書にのみ作用し、外部システムには何もしません。

## ダッシュボードの見方
- 件数：「未解決のインシデント」「承認待ちの対応」「有効なアドレス遮断」
- 「インシデント」表：「重大度」（緊急・高・中・低）、「ルール」、「対象」、「概要」、「状態」、「最終検知」
- ルール：サインイン失敗の繰り返し、パスワードスプレー攻撃、セッショントークンの不正利用、権限の探索、管理操作の集中、
  文書の完全性エラー、監査チェーンの破損、アップロードの不正利用、抽出失敗の繰り返し、通常と異なる書き出し

## 封じ込め
| 対応 | 既定の動作 |
|---|---|
| 「ユーザーのセッションを終了」 | 自動 |
| 「アドレスを遮断」（60 分、サインインのみ） | 自動。ただし、有効な管理者が直近 24 時間に使ったアドレスは要承認 |
| 「文書を隔離」 | 自動 |
| 「アップロードを制限」（60 分） | 自動 |
| 「抽出を一時停止」（30 分） | 自動 |
| 「管理者に通知」（アプリ内） | 自動 |
| 「アカウントをロック」 | 要承認 |
| 管理操作の集中を検知した管理者のセッション終了 | 要承認 |

対応の状態：「承認待ち」「実行済み」「却下」「取り消し済み」「ポリシーにより拒否」（最後の有効な管理者のロックなど）

## インシデントに対応する
対象：MFA 済みセッションの管理者
1. インシデントを開き、概要と対応内容を確認します。
2. 「コメント」を入力します。
3. 「承認待ち」の対応は「承認」または「却下」を選択します。
4. 実行済みの「アカウントをロック」「アドレスを遮断」「アップロードを制限」「抽出を一時停止」は「元に戻す」で
   取り消せます。
5. 「解決」でインシデントを閉じるか、「誤検知」として記録します。

インシデントの状態：「未解決」「封じ込め済み」「解決済み」「誤検知」。記録が削除されることはありません。

## 緊急時
管理者がロックまたは遮断されてしまった場合は、運用者が `kizuna-admin emergency-unlock <組織>` を実行します。
管理者の再有効化と遮断の解除が行われ、この操作も監査証跡に記録されます。

インシデントで隔離された文書の解除については、[文書のアップロード](03-uploading-documents.md#隔離される主な理由)
を参照してください。
