# 管理

このページの変更操作には、管理者ロールと MFA 済みセッションが必要です。すべての変更は監査証跡に記録されます。
監査担当は「ユーザーと権限」を閲覧できますが、変更はできません。

## ユーザー
画面：「管理」›「ユーザーと権限」

| 作業 | 方法 |
|---|---|
| ユーザーの追加 | 「ユーザーを追加」で氏名、メールアドレス、ロール、「初期パスワード」（12〜128 文字）を入力します。パスワードは別の経路で本人に伝えてください。 |
| ロールの変更 | 行でロールを選び直します。そのユーザーのセッションは即時に終了します。 |
| 無効化／有効化 | 「無効化」すると即時にサインアウトされ、サインインできなくなります。「有効化」でアクセスが戻り、ロックも解除されます。 |
| セッション終了 | 「セッション終了」で、すべての端末からサインアウトさせます。 |
| セッションの確認 | 「セッション」で有効・終了済みのセッションと、MFA の有無を確認できます。 |
| 認証アプリのリセット | 「認証アプリをリセット」で認証アプリとセキュリティキーの登録を削除します。本人は再登録が必要です。自分自身はリセットできません。 |

最後の有効な管理者は、削除・無効化できません。サインインの失敗でロックされている場合は「ロック期限」に表示されます。

## 認証アプリ（TOTP）の登録 — API のみ
現時点では登録画面はありません。
1. 現在のパスワードを付けて `POST /api/v1/auth/mfa/totp/setup` を呼び出すと、認証アプリ用のシークレットが返されます。
2. 認証アプリに表示されたコードを付けて `POST /api/v1/auth/mfa/totp/confirm` を呼び出すと、登録が完了します。
3. 以降は「認証コード」を入力してサインインします。

## セキュリティキー（API のみ）
セキュリティキー（WebAuthn）は、フィッシングに強い任意の第 2 要素です。
- 登録：`POST /api/v1/auth/mfa/webauthn/register/start`（現在のパスワードが必要）→ `…/register/finish`。
  登録が完了すると、そのユーザーのセッションはすべて終了します。
- 登録後は、パスワードと認証コードによるサインインは拒否されます。`/api/v1/auth/webauthn/login/start` と
  `…/login/finish` でサインインします。**Web のサインイン画面はまだ対応していません。** Web 画面を使う必要がある
  ユーザーには、セキュリティキーを登録しないでください。

## リカバリーコード
- 最初にセキュリティキーを登録したとき、**使い捨てのリカバリーコードが 10 個、一度だけ** 返されます。オフラインで
  保管してください。
- キーを紛失した場合：パスワードとリカバリーコード 1 つを付けて `POST /api/v1/auth/webauthn/recover` を呼び出します。
  すべてのキーが削除され、セッションも終了し、MFA 未確認のセッションが発行されます。特権操作の前に第 2 要素を
  登録し直し、改めてサインインしてください。
- その他の復旧手段：別の管理者が「認証アプリをリセット」を実行します。サインインできる管理者がいない場合は、
  運用者が `kizuna-admin reset-mfa <組織> <メールアドレス>` を実行します（ロックの解除は
  `kizuna-admin unlock <組織> <メールアドレス>`）。

## 取込設定
画面：「管理」›「取込設定」。抽出時に CSV・XLSX・PDF ファイルをどう読み取るかを設定します。

| グループ | 設定 | 範囲／既定値 |
|---|---|---|
| 全般 | 「既定の文書種別」 | 既定：仕様書 |
| 全般 | 「アップロード上限（MB）」 | 1〜200、既定 25（保存のみ。実際の上限は運用者がサーバーで設定） |
| CSV | 「区切り文字」 | カンマ、セミコロン、タブ |
| CSV | 「文字コード」 | UTF-8 または Shift_JIS |
| CSV | 「見出し行（0 = なし）」 | 0〜100、既定 1 |
| CSV | 「最大レコード数」 | 1〜20,000 |
| XLSX | 「シート名」 | 空欄で「全シート」 |
| XLSX | 「見出し行」「最大シート数」「最大レコード数」 | 0〜100、1〜50、1〜20,000 |
| PDF・スキャン画像 | 「テキスト層のないページに OCR を実行」 | 既定でオン |
| PDF・スキャン画像 | 「OCR 言語」 | 日本語 + 英語、日本語、英語 |
| PDF・スキャン画像 | 「最大ページ数」 | 1〜500 |
| 列の対応付け | 部品識別子・属性・値・単位・リビジョンの列 | 見出し名。単位とリビジョンは任意 |

- 「設定を保存」で新しいバージョンとして保存されます（「バージョン n として保存しました。」）。他の人が先に保存して
  いた場合は最新の内容が読み込まれるので、確認してから保存し直してください。
- 新しい設定は次回の抽出から適用されます。処理済みの文書には「再抽出」を使います。
- 「設定を書き出し（JSON）」でフォームの内容をダウンロードできます。「既定値に戻す」は保存前の変更を破棄します。

## タイムゾーン

「連携 › タイムゾーン」で組織の IANA タイムゾーン（既定 `Asia/Tokyo`）を設定します。有効期限の判定で「今日」が
どの日になるか、レポートの開始日・終了日がどう解釈されるかが決まります。MFA 済みセッションの管理者のみ。変更は
すべて版管理・監査され、セキュリティイベントが記録されます。

## AI 支援抽出
「取込設定」画面の下部にあるパネルです。既定ではオフです。

ルールで認識できなかったラベルを外部の AI プロバイダーへ送り、どの項目に当たるかを提案させる機能です。有効にするには
2 段階のスイッチが必要です。運用者がサーバーにプロバイダーを設定し、そのうえで管理者が組織として有効にします。
「運用者により未設定です。」と表示される場合は、1 段階目が設定されていません。

**データ処理に関する通知 — 有効にする前に必ずお読みください。** パネルには、運用者が公開したプロバイダーのデータ処理に
関する通知が、原文のまま（翻訳せずに）バージョン付きで表示されます。本ビルドでの扱いは次のとおりです。
- 送信される内容：認識できなかったラベル最大 100 件と、それぞれ最大 2 件の値の例。メールアドレス、URL、電話番号、
  住所、および人に関するラベルの値は `[personal]` に置き換えられます。認識済みのラベル（部品番号、サプライヤー、
  承認者など）は送信されません。置き換えは経験則に基づくため、自由記述内の氏名などは検出できない場合があります。
- 無料のプロバイダーは、受け取ったデータを記録・保持し、学習に使う可能性があります。データ処理契約はありません。
- 機密情報、輸出管理対象の情報、個人情報を含む文書では有効にしないでください。

有効にするには、「プロバイダーのデータ処理に関する通知（バージョン n）を読み、この組織として同意します。」に
チェックを入れ、「AI 支援抽出を有効にする」を選択します。通知が更新されると「有効ですが稼働していません。」と表示
されるので、「通知に同意して有効のままにする」で新しい通知に同意します。「AI 支援抽出を無効にする」で直ちに停止
できます。パネルには、プロバイダー、モデル、ホスト、「1 日の上限」、「本日の使用量」も表示されます。

AI ができること・できないこと：
- ラベルを項目に対応付けるだけです。値は常に文書から取得します。
- 承認、レビュー状態、有効期限、リビジョン、検査結果といった管理上重要な項目には対応付けません。
- AI によるクレームは「ai suggested」（AI 提案）として保存され、信頼度は最大 70% です。矛盾検出の対象外で、
  アップロードした人以外のレビュアーが承認するまで判断の根拠として引用できません（承認は現バージョンでは **API のみ**）。
- プロバイダーの障害や上限到達の場合は、ルールのみで抽出を続けます。

## 検知しきい値
「管理」›「セキュリティ監視」画面のパネルです（管理者のみ）。
- 各ルールは、期間内のイベント数が「しきい値」に達するとインシデントを発生させます。対象は、アカウントごとのサインイン
  失敗、ロックまでのサインイン失敗、パスワードスプレー（失敗数・アカウント数）、権限拒否、特権操作、アップロード、
  抽出失敗、エクスポートです。各欄に範囲と既定値が、「現在の値」に適用中の値が表示されます。
- 「ロックまでのサインイン失敗」は、総当たりのしきい値以上にする必要があります。
- 「適応型しきい値」は、最近のベースラインに基づいて量的ルールを引き上げるだけで、引き下げはしません。上限は
  「最大倍率」です。「ベースライン（日）」で対象期間を指定します。
- 「しきい値を保存」で新しいバージョンとして保存し、「既定値に戻す」で既定値に戻します。
