# 矛盾とレビュー

矛盾とは、証拠の中で KIZUNA が見つけた食い違いや欠落です。結論ではなく、人がレビューするためのきっかけです。
画面：「矛盾」›「矛盾レビュー」

## 矛盾を見つける
1. 「検証を実行」を選択します（管理者、レビュアー、アナリスト）。新しい矛盾の件数と、解消した件数が表示されます。
2. 「状態」で絞り込みます：「未解決」「証拠待ち」「解決：承認」「解決：却下」「対象外」
3. 矛盾を選択して開きます。

種別：リビジョン不一致、単位の不整合、値の不一致、公差逸脱、承認の欠落、証拠の期限切れ、適用範囲の誤り、
サプライヤー記録の矛盾、検査結果の矛盾

## 矛盾の内容を読む
| 項目 | 内容 |
|---|---|
| 「検出内容」 | 種別、識別子、属性。 |
| 「理由」 | ルールによる説明。 |
| 「根拠となる出典」／「矛盾する出典」 | それぞれの値・文書・位置。承認の欠落や証拠の期限切れのように、出典が 1 つだけのルールもあります。 |
| 「信頼度と限界」 | 出典の最低信頼度。 |
| 「人によるレビュー」 | 判断がまだ必要かどうか。レビュアーが判断するまで、そのレコードは先に進めません。 |
| 「影響を受ける可能性のある判断」 | これらのクレームに依拠している記録済みの判断。 |

## レビューを記録する
対象：MFA 済みセッションの管理者またはレビュアーで、その証拠を提供していない人（4つの目の原則）
1. 「理由」を入力します。承認・却下には必須で、監査証跡に保存されます。
2. 次のいずれかを選択します。
   - 「特例として承認」：差異を記録付きの例外として受け入れます。状態は「解決：承認」になります。
   - 「証拠を却下」：証拠が誤っていると判断します。状態は「解決：却下」になり、誤ったクレームは却下されて判断の
     根拠から外れます。そのクレームに依拠していた判断は「影響の可能性」になります。
   - 「追加証拠を依頼」：新しい証拠が届くまで、状態を「証拠待ち」にします。

**既知の制限**：「証拠を却下」には、誤ったクレームの ID をサーバーへ送る必要がありますが、現在の画面は送信しません。
そのため、このボタンは「リクエストに失敗しました（faulty_claims_required）。」となります。修正されるまでは API で
却下してください：`POST /api/v1/conflicts/{id}/review`（`decision: "reject"`、`comment`、`faulty_claims` を指定）

「この矛盾は既にクローズされています。」と表示された場合は、他の人が先にレビューしています。一覧を再読み込みして
ください。
