# Entity resolution v2 vs v1 — 2026-11-05

Evidence label: **SIMULATED** data (synthetic, deterministic generators), **MEASURED** quality and timings from one
real run of `kizuna-er-compare` at commit d8e4618 (release build, 5 runs per dataset, median wall time).
Raw output with provenance: `reports/er/er_v2_compare.json`. Nothing below is typed by hand except the prose.

## What changed

| | v1 (kept, `KIZUNA_ER_VERSION=v1` or `?version=v1`) | v2 (default) |
|---|---|---|
| Blocking | shared keys (normalised, loose, revision-stripped, single-deletion variants) | sorted neighbourhood (forward + reversed keys, window 4) ∪ normalised prefix (cap 64) ∪ bigram index (stop-grams > 256, ≥ 50 % shared) |
| Parts | case/width, separator, revision suffix, 1-edit (≥ 6 chars) rules | + zero-width removal, dash variants (‐ – − ー ｰ), OCR fold (O/0, I/l/1, S/5, B/8, Z/2, G/6), revision split; 4 comparison fields |
| Suppliers | same rules as parts | legal forms (株式会社/(株)/㈱/（株）/有限会社/㈲/合同会社, Co., Ltd./K.K./Inc./Corp./Y.K./G.K./LLC), half-width → full-width kana, hiragana → katakana, small-kana and long-vowel folding, itaiji table (髙/高, 﨑/崎, 齋/斎 …), Hepburn romaji of kana names with spelling/long-vowel folding; fields: written form, romaji, legal form |
| Scoring | fixed rules | Fellegi–Sunter weights, m/u/p by EM on blocked + seeded random pairs (cap p ≤ 2·n/training pairs); checks: converged, likelihood monotone, p in range, classes separated — else prior parameters |
| Thresholds | — | FS error-rate rule (μ = 0.001 false-match mass above t_match, λ = 0.01 match mass below t_possible, t_possible ≥ 0) |
| Outcomes | match / possible / review | match / possible / requires review (ambiguous cluster, revision differs, legal form differs) / no match |
| Merging | never automatic | never automatic: only `safe` pairs (identical after identity-preserving normalisation) skip review; FS `match` is listed for a human decision |

## Datasets

- **E2E generator** (`scripts/e2e/gen_dataset.py`, seeds 7/24, 11/48, 13/400 parts): part ids plus the injected
  `duplicate_component_id` variants from `ground_truth.json`.
- **JA suppliers** (`er_eval::ja_suppliers`, seed 20261105, 300 entities): invented place + business names
  (30 × 15 words, e.g. 東海 + 精機), 1–4 surface forms each: legal-form notation/position, itaiji, full-width space,
  legal form dropped, katakana reading, half-width katakana, enlarged small kana / ー, romaji (Hepburn, macron,
  upper case). Hard negatives occur naturally (same place or same business; 工業/興業 are homophones).
- **JA parts** (`er_eval::ja_parts`, 1 000 and 5 000 entities): three number formats; ~20 % have a one-digit
  sibling that is a *different* part; variants: full-width, zero-width, dash variants, separator removed/space,
  lower case, revision suffix (same part), OCR confusion, and rare non-OCR keying errors.

Predicted = every pair a version surfaces (any outcome except no match); truth = all pairs of distinct strings of
one entity. "Same-script recall" leaves out pairs between a kanji form and a kana/Latin form: neither version has a
reading dictionary, so those are unreachable by design.

## Reading the results

- **E2E generator:** both versions find every injected duplicate with no false pair. The generator only injects
  separator-removed ids, which v1 already handled; v2 compares more pairs (blocking is broader) at no quality cost.
- **JA suppliers:** v1 finds 11.8 % of true pairs; v2 finds 44.6 % overall and 100 % of same-script pairs, at
  precision 0.843 (v1 0.918 on far fewer predictions). The remaining false pairs are mostly homophones
  (サクライコウギョウ vs SAKURAI KŌGYŌ where the entity is 興業 vs 工業) and same-place names with similar romaji —
  a human must decide these anyway. Recall above ~45 % overall needs kanji readings (out of scope; no dictionary).
- **JA parts:** v2 F1 0.981 / 0.982 vs v1 0.842 / 0.819. v1's false pairs are mainly one-digit siblings (its 1-edit
  rule); v2 learns that a digit difference is strong evidence of a different part. Trade-off: v2 recall of
  non-OCR keying errors is 0 (v1 ~0.8) — such a typo is indistinguishable from a sibling part. v2's few false pairs
  are distinct parts whose numbers differ only by separators (KZ-14641 vs KZ14-641), flagged as possible matches.
- **EM:** converged with monotone likelihood on all six datasets (`em` in the JSON); no fallback to priors was
  needed. On parts the classes are almost perfectly separated, so weights are extreme and t_match = t_possible.
- **Cost:** v2 compares 10–92× more pairs than v1 and is 2.4–6× slower (459 ms vs 143 ms median for 11 584 keys,
  release build, shared host with load average ~10). Both are far below the 60 s request timeout at the API's
  5 000-key limit.

## Limits

- Synthetic data only; real supplier masters will have other variant mixes. Thresholds are the FS error-rate rule
  with a priori μ/λ, not tuned on these sets.
- EM assumes conditional independence of fields; the part fields are correlated, which inflates weights.
- Kanji ↔ kana/romaji equivalence needs a reading dictionary; ツ-for-ッ in kana breaks romaji equality.

```
for c in "7 24" "11 48" "13 400"; do set -- $c; python3 scripts/e2e/gen_dataset.py --seed $1 --parts $2 --out /tmp/e2e_$1; done
cargo build --release -p kizuna-bench --bin kizuna-er-compare
target/release/kizuna-er-compare --runs 5 --e2e e2e_seed7_24=/tmp/e2e_7/ground_truth.json \
  --e2e e2e_seed11_48=/tmp/e2e_11/ground_truth.json --e2e e2e_seed13_400=/tmp/e2e_13/ground_truth.json \
  --out reports/er/er_v2_compare.json
```
